# Cantor

Cantor is an emerging SOP semantic coprocessor: a local, provider-independent control layer that supplies verified Subject-Oriented Programming definitions and operations to a neural inference model.

Cantor is designed to:

- compile governed SOP source into signed semantic packages;
- resolve subjects and perspectives through a typed semantic fabric;
- demand-load the smallest applicable SOP operation through `sop_query`;
- direct a replaceable inference provider such as Ollama;
- validate proposed judgments against meaning, evidence, constraints, and authority;
- preserve pertinent history, reflective review, provenance, and reentry state; and
- prevent unsigned or uncompiled content from acquiring semantic or executable authority.

## Current status

Cantor is specification-rich but does not yet have a runtime implementation. The current authorized implementation boundary is one local proof:

1. one test-signed compiled SOP package;
2. one in-memory semantic fabric;
3. one slim signed primer and `sop_query` tool;
4. one subject unfolded through two SOP queries;
5. one deterministic inference-provider mock;
6. one reflective review capsule; and
7. one append-only transition trace.

The database, embeddings, Ollama adapter, faculty runtime, distributed execution, and learned graph propagation remain deferred until that proof passes.
