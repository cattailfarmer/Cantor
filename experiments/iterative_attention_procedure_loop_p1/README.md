# Iterative attention procedure loop P1

This experiment fixes the provider-free Slice 2 fixture at eight procedure steps per call. The deterministic driver performs one READY advance followed by one terminal advance and exact READ.

`artifacts/deterministic_drive_measurement_v1.json` is regenerated by:

```text
cargo run -p cantor_compact_reflection_loop -- measure-iterative-fixture
```

The measurement separates compact projections that a later provider loop may import from exact state retained under host custody. It does not claim that a provider was called or that structural replay is causal re-execution.

`artifacts/iterative_transcript_measurement_v1.json` is regenerated by:

```text
cargo run -p cantor_compact_reflection_loop -- measure-iterative-transcript-fixture
```

This second provider-free measurement records the three provider-shaped pass envelopes and compares their compact UTF-8 JSON sizes with exact terminal custody. Bytes are not model tokens, latency, memory, or reasoning-quality evidence.

`artifacts/attention_reentry_measurement_v1.json` measures an experimental digest-bound attention reentry frame over a fourteen-pass quota-one fixture. The full transcript remains authoritative. The compact request preserves the objective, current frame, latest assistant/tool pair, quota, tool schema, phase, and terminal response schema; it does not establish semantic output equivalence or provider compatibility.

Slice 6C adds a dual-transcript projection in `dual_transcript.rs`. It keeps each canonical full-prefix request as replay authority while recording the request that an experimental compact transport would present to a model. The first pass remains full-prefix; subsequent continuation and terminal-reflection requests use replay-derived compact frames. This is a provider-free structural projection, not evidence of provider execution or semantic equivalence.

Slice 6D adds self-digested transport envelopes in `transport_envelope.rs`. Domain-separated request and frame hashes support a cheap local corruption check. A separate validator reconstructs each envelope from the validated Slice 6C projection; consequently, a locally coherent substitution can pass local integrity while still failing canonical binding. These content hashes are not producer signatures or proof of provider execution.

Slice 6E adds an effectless lifecycle in `dispatch_lifecycle.rs`: prepared, fixture-dispatch-recorded, fixture-response-recorded, and canonically admitted. The fixture marker and supplied response are pure values. They deliberately make no physical-provider claim; a real adapter remains a separately governed future boundary.

Slice 6F adds digest-bound lifecycle checkpoints in `dispatch_checkpoint.rs`. A phase determines exactly one next operation, and provider-free resume covers every remaining transition. The checked corpus contains 12 cases—four lifecycle phases for each of two iteration transports and terminal reflection—and compares every resumed trace with an independently reconstructed uninterrupted trace.

`artifacts/dispatch_checkpoint_handle_measurement_v1.json` is regenerated by:

```text
cargo run -p cantor_compact_reflection_loop -- measure-dispatch-checkpoint-handles
```

Slice 6G measures minimal host-custody checkpoint handles. The 12 handles total 11,963 compact JSON bytes versus 70,830 bytes for full checkpoints, or 16.88 percent of the full serialized size. The handle cannot resume independently and the byte result is not token, latency, memory, or model-quality evidence.

`artifacts/provider_free_attention_lineage_index_v1.json` is regenerated by:

```text
cargo run -p cantor_compact_reflection_loop -- index-provider-free-lineage
```

Slice 7A is the digest-only table of contents for eleven provider-free fixture artifacts. It commits 1,396,447 bytes of generated bodies through a 5,139-byte index and records a strict capability ledger. It does not embed the indexed requests, responses, checkpoints, registries, or messages.

Slice 7B adds `checkpoint_custody.rs`, an immutable in-memory BTreeMap from checkpoint digest to exact bound handle and checkpoint. All 12 fixture handles resolve and resume to their uninterrupted traces. This makes the compact handle operational without claiming a physical database, persistence, service, or reconstruction of meaning from a hash.

Slice 7C adds `custody_query.rs`, a strict four-operation request/response protocol over a supplied custody registry. `inspect` returns compact metadata; `resolve` explicitly returns full host custody; `resume_iteration` and `resume_terminal` accept their distinct transports and return deterministic admitted traces. `query-scripted-checkpoint-custody` reads at most one MiB of strict JSON from stdin and writes one digest-bound response to stdout. It is a provider-free tool seam, not live model integration or a database service.

`artifacts/custody_query_surface_measurement_v1.json` is regenerated by:

```text
cargo run -p cantor_compact_reflection_loop -- measure-checkpoint-custody-query-surface
```

Slice 7D measures every paired inspect and resolve result. Inspect responses total 21,905 normalized JSON bytes versus 112,978 for full resolve responses: 19.39 percent, with 91,073 bytes omitted. Individual inspect results span 1,807–1,840 bytes. These are fixture UTF-8 byte counts, not token, memory, latency, quality, or live-provider evidence.

cargo run -p cantor_compact_reflection_loop -- describe-provider-free-shell-release

Slice 7E publishes additive release root `b173777725ecf99c48038de2023c71b49dd55db4458b73d3f8d4585781c63e36`.
